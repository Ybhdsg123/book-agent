# 热点采集与选题评分（第一阶段）

## 目标
把豆瓣、公众号、微博、小红书、B站、X 等来源采集到的公开/授权数据转换为统一格式，保留证据和时间，再做跨平台去重与公众号适配评分。单个平台失败不能拖垮整轮任务。

## 当前实现
- `core/hotspots/normalize.mjs`：统一字段、平台名、时间、链接、互动指标和证据级别。
- `core/hotspots/collector.mjs`：并行调用独立 Adapter，分别记录成功、部分成功、失败和无效条目。
- `core/hotspots/dedupe.mjs`：按规范化 URL 和标题相似度聚类，保留多平台来源。
- `core/hotspots/scoring.mjs`：输出总分、分项、缺失信号和证据置信度。

## 评分维度
| 维度 | 权重 | 评分依据 |
|---|---:|---|
| 平台内传播表现 | 25 | 榜单名次、阅读/播放/互动数据 |
| 增长趋势 | 20 | 不同采集时点的热度/互动变化 |
| 情绪共鸣 | 20 | 根据原始内容判断 |
| 内容延展性 | 15 | 能否与书籍观点、作者故事、阅读体验结合 |
| 公众号适配度 | 15 | 是否符合图书/成长/生活观点账号定位 |
| 时效性 | 5 | 采集时间与发布时间 |

每项使用 0–5 分，再按权重折算。缺失维度不填猜测值：总分按已提供维度折算，同时列出缺失项。平台热度原始值不跨平台直接比较；榜单名次只在同一平台榜单范围内解释。

分数档位：85–100 优先研究；75–84 候选；60–74 观察；低于 60 暂不处理。分数之外必须展示证据置信度。

## 必须保留的证据字段
平台、标题、原始链接、作者/账号、摘要、发布时间、采集时间、榜单名次与榜单总量、播放/阅读/点赞/评论/转发/收藏数据、采集方式、适配器 ID、来源页面。

## Adapter 接口
```js
{
  id: 'weibo-public-board',
  platform: 'weibo',
  async collect({ since, limit }) {
    return [{ title, url, publishedAt, metrics, evidenceLevel }]
  }
}
```

## 尚未完成的部分
当前只实现 Adapter 契约和统一处理框架，**尚未接入六个平台的真实 Connector**，也未部署定时任务。不能把模拟数据或框架测试说成真实平台采集成功。

## 安全与降级
- 优先官方 API、平台公开页面和用户授权会话。
- 不实现验证码绕过、Cookie 池、账号轮换或规避平台访问控制。
- 登录失效、限流、页面结构变化应作为独立平台错误记录。
- 数据过期、指标缺失、来源不明时降低置信度并明确展示。
- 每日选题推送只选出有来源、有采集时间、适配分和证据置信度的候选。
- 深度研究前打开原始来源核对内容；搜索摘要不能代替正文。
